# Agent skill

The instructions an agent follows are `SKILL.md` in the repository root. The site serves that file at `/SKILL.md` (`text/markdown`) and renders the same text at `/skill`.

`llms.txt`, the README, `/agents`, and the OpenAPI description link to it. `tests/skill.test.mjs` checks that every field, enum, endpoint, and error code named there exists in the API, and that the skill's example request returns HTTP 200.

`who` accepts a string or a list of names, and it should name only the people who appear in that shot. Set `time` (`dawn`, `morning`, `midday`, `afternoon`, `dusk`, `evening`, `night`) when the story names the time of day. It drives the light line and carries forward. Prose on the rules path uses the same carry, including midday, afternoon, entardecer, and pôr do sol. Entardecer and crepúsculo are dusk. `evening`, `morning`, `afternoon`, and `midday` in `light` are stored as `time`. Set `light` for a lighting quality. One action beat is one shot: count them and do not merge or drop beats. Send the whole scenario in one request. A warning `action` of `none` means the board is done. Any re-post must resend every scene. Keep sending `scenario.characters` first. A story longer than 40 shots is split into parts of at most 40. Send the full story as one scene per beat. When the story names people, send scenario character sheets (age, every garment, carried items, distinctive features, and `locks` with `fromOrder`) and do not send `input` `prose`. Prose is only for a premise that names nobody. `format` `agent` on prose returns HTTP 200 with `sheets_missing` and the sheets to resubmit. Do not shorten the story or drop actions. `invalid_plan` says how to resubmit. `GET /api/v1/storyboard` does not plan a board and points to `POST`. A board with far fewer shots than the sentences in the premise adds a `short_board` warning. An explicit morning or dawn cue replaces a carried night. The lock version in force repeats age, every garment still worn, every carried item, and role on each shot of that character, including Part 2. Before the shots, fill one complete character sheet per character: name, age, every garment, carried items, and distinctive features, using the scenario character fields. A sheet that omits an age, garment, or carried item the story names is filled from that text. The response is 200, and each addition is a warning with `character`, `field`, `value`, and `source`. Nothing is invented. `strict_sheet` true keeps HTTP 400 `invalid_scenario`. The message names the character, the field, and the missing text. Lock lines are an ordered list of versions. A new version starts when the character puts on, changes, or takes off a garment, or picks up, drops, carries, or hands an item, and earlier shots keep the previous version across parts. The object of a carry, hand, pick-up, or drop verb starts an item version when it is any concrete noun, such as a letter, a pastry, a key, or a basket, in English or Portuguese. An abstract noun or a place is not an item. A note such as `coat removed` removes only that garment, and `puts on a plum cloak` adds only that garment. Age, every other garment, and every carried item stay. A story `takes off`, `tira`, or `despe` does not raise `undeclared_wardrobe` when the versioned lock already applied that change. A plain prose request still plans, and the rules engine does not copy a trait from one character to another. Kiln, forno, and fornalha are places. A definite locative with an unknown place noun still produces a PLACE line. `Mara applauds` and Portuguese `veste o fato` are each one shot. A hair phrase, a garment led by a or an, and a noun phrase such as jaqueta de couro stay in that line. A later sentence that uses the item does not replace it. A scenario that packs many action beats into few shots is HTTP 400 `invalid_plan`. A premise that names people or actions and cannot be planned is HTTP 400 `invalid_plan`, not a placeholder board. The message names every dropped person and quotes every dropped action, each one ending in a period (`This action was not planned: "Maya hands Rui a letter on the quay".`). Scene `what` and `who` count in that check. `characters`, `places`, and `scenes` sent at the top level, instead of inside `scenario`, are HTTP 400 `misplaced_scenario_fields`. The message names each field and shows the shape to use. That error outranks `invalid_premise` when the premise is missing. Age and role stay on the character lock line. A negative constraint such as "without touching" stays in the short and the detailed prompt. A shot size written in the action is used once, and the response warns with `shot_size_in_action`.
