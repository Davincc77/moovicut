# Agent skill

The instructions an agent follows are `SKILL.md` in the repository root. The site serves that file at `/SKILL.md` (`text/markdown`) and renders the same text at `/skill`.

`llms.txt`, the README, `/agents`, and the OpenAPI description link to it. `tests/skill.test.mjs` checks that every field, enum, endpoint, and error code named there exists in the API, and that the skill's example request returns HTTP 200.

`who` accepts a string or a list of names, and it should name only the people who appear in that shot. Set `light` on every shot. One action beat is one shot: do not merge beats. A story longer than 40 shots is split into parts of at most 40. Send the full story as one scene per beat or as plain prose (`input` `prose`) so every beat is split automatically. Do not shorten the story or drop actions. `invalid_plan` says how to resubmit. `GET /api/v1/storyboard` does not plan a board and points to `POST`. A board with far fewer shots than the sentences in the premise adds a `short_board` warning. An explicit morning or dawn cue replaces a carried night. A lock line repeats age, every garment, every carried item, and role on every shot of that character, including Part 2. Before the shots, fill one complete character sheet per character: name, age, every garment, carried items, and distinctive features, using the scenario character fields. A sheet that omits an age, garment, or carried item the story names is HTTP 400 `invalid_scenario`. The message names the character, the field, and the missing text. A plain prose request still plans, and the rules engine does not copy a trait from one character to another. Kiln, forno, and fornalha are places. A definite locative with an unknown place noun still produces a PLACE line. `Mara applauds` and Portuguese `veste o fato` are each one shot. A hair phrase, a garment led by a or an, and a noun phrase such as jaqueta de couro stay in that line. A later sentence that uses the item does not replace it. A scenario that packs many action beats into few shots is HTTP 400 `invalid_plan`. A premise that names people or actions and cannot be planned is HTTP 400 `invalid_plan`, not a placeholder board. The message names every dropped person and quotes every dropped action, each one ending in a period (`This action was not planned: "Maya hands Rui a letter on the quay".`). Scene `what` and `who` count in that check. `characters`, `places`, and `scenes` sent at the top level, instead of inside `scenario`, are HTTP 400 `misplaced_scenario_fields`. The message names each field and shows the shape to use. That error outranks `invalid_premise` when the premise is missing. Age and role stay on the character lock line. A negative constraint such as "without touching" stays in the short and the detailed prompt. A shot size written in the action is used once, and the response warns with `shot_size_in_action`.
